# Visual benchmark v1 contracts

`schema.json` is the versioned contract index. It names the JSONL record types
used by capture and annotation workers: `entity_capture`, `candidate`,
`visual_instance`, `mapping`, `label`, `adjudication`, and `rejection`.

`enums.json` is the canonical vocabulary for labels and rejection stages.
Workers must preserve `schema_version: "visual-benchmark-v1"`, stable IDs,
and provenance on every record. The schema is intentionally extensible so
capture code can add diagnostics without changing the identity of a record.

Positive-first review packets use `review_attestation` labels to confirm that
the entity's frozen screenshots, overlays, and uncertain crops were reviewed.
For an exact instance-to-candidate mapping, the visual-instance identity is
derived from the candidate identity in the same reviewer/pass and records an
`identity_derivation` containing the mapping, candidate, and candidate-label
IDs. The validator checks those cross-record references. Older pilot labels
without a derivation or attestation remain valid through the v1 migration path.
The label-ID hash namespace remains `visual-review-packet-v2`; v3 is a separate
workflow/provenance and draft-storage version, so canonical pilot IDs do not
change.

The future ranker-safe packet is versioned as
`visual-review-packet-v4-ranker-safe`; it also keeps the v2 label-ID namespace.
Its candidate labels are normalized and validated with these invariants:

- `wrong` identity has no roles, all five `best_for_role` values false, and
  both theme usabilities `unusable`;
- `ambiguous` identity and candidates unusable on both themes have no best
  roles;
- every true best role is present in `roles`, has `correct` identity, and has
  at least one `good` or `conditional` theme;
- `quality_defects` cannot encode an evidence limitation such as
  `no_verified_raster_preview`;
- in one reviewer/pass scope, `not_missing` requires a same-scope correct,
  role-eligible, usable candidate. If such a discovered candidate is unusable
  on both themes, the missing cause is `rejected_by_shape_or_quality` rather
  than `no_graphic_asset_exists`.

These checks are activated only by the v4 workflow/prompt provenance. Legacy
pilot, round-two, and round-three raw rows remain valid and are never rewritten.
Use `scripts/visual-review-packet.mjs --workflow-version
visual-review-packet-v4-ranker-safe` to create a new judgment-free packet.

For non-exact or unmapped observations, the review UI asks whether the visible
content is a requested-company logo/brand mark: `yes`, `no`, or `unclear`.
Exports serialize those decisions to the existing `correct`, `wrong`, and
`ambiguous` identity values. Capture fields such as region, theme, visibility,
and mapping confidence remain evidence unless the reviewer records an override.

`benchmark-manifest.json` owns the immutable split and shard assignment. Its
`shards[].assignment_file` paths are under `shards/assignments/`; browser
capture evidence must use `captures/`, `captures.jsonl`, or another explicitly
declared evidence path and must never overwrite assignment files. The browser
worker's operational `manifest.json` is described separately by
`capture-manifest.schema.json`.

Assignment files generated by `scripts/visual-benchmark-shards.mjs` use the
additional `capture_assignment` record type. Assignment records are not
capture evidence and must not be mistaken for successful page captures.
